# Sacred Bloom content and implementation notes

## Authority and exact wording

The owner’s Sacred Bloom brief (2026-09-26) is the authoritative content supplied for this pass. No finalized Sacred Bloom content files were present in the repository. `content/brand.ts` holds the exact brand name, philosophy, ownership line, preferred labels, heart story and Wonder Card line. Do not pass these through rewriting tools.

The heart narrative and Wonder Card are **draft** creative material whose wording is **protected**. Approval status and permission to rewrite are separate. Tests compare the catalog against the authoritative wording, including paragraph and line breaks.

## Existing architecture preserved

React/Vinext, D1 product JSON overrides and revisions, R2 uploads, analytics, the saved bag, history URLs, media carousel, original photos/films, and framing controls remain. No dependencies or database schema were added. The existing session cookie name and stone IDs remain for continuity. The hosting URL retains its old slug so shared links keep working; the customer-facing identity is Sacred Bloom.

`lib/product.ts` extends existing fields rather than replacing the data model. Existing `title`, `subtitle`, `description`, `images`, `videos` and `hero` are the name, introduction, story and media fields. Added fields cover editorial status, optional factual data, independent Wonder Cards, future optional narration, descriptive alt text, currency, availability, unique inventory and copy protection. Narration is modeled but no audio is synthesized or displayed.

Database records without `contentVersion` adopt the new metadata on read. Seller edits and uploaded covers survive. Original prototype prose/names remain in `prototypeContent`; the admin can inspect/export them. Revisions and legacy backups remain supported. Explicit locked-copy checks apply to normal saves, imports and revision restores. An approved replacement of locked copy needs a deliberate engineering/content change; there is no casual unlock control.

## Remaining placeholders — do not invent

- All 28 names remain `placeholder` until Sacred Bloom approves final names. The heart uses **Clear Quartz Heart**; Midnight Orbit uses **Dark / Smoky Sphere**. Their previous names remain in prototype history. Other existing prototype names are retained, not newly approved.
- Except for the supplied heart narrative, product stories remain pre-existing draft/prototype copy, awaiting Sacred Bloom approval. No bulk regeneration occurred.
- The heart's material and features come from the owner’s example. Other identification text is provisional visual assessment. No weight, dimensions, geographic origin, supplier, age, rarity, sustainability or healing claims have been added.
- All prices are existing demonstration fixtures, with placeholder metadata. Admins must explicitly mark seller-confirmed prices. New items default to an unpublished record with an unconfirmed zero-price fixture requiring a seller-entered price before launch.
- Inventory counts and one-of-one flags are unspecified until confirmed. Admins can set inventory and availability. Sold/zero-stock items remain viewable but cannot be added; confirmed unique items have a one-per-bag cap.
- A bag is not a reservation. No payment provider, tax/shipping configuration, order processing, reservation transaction or payment webhook exists. No checkout has been fabricated. A future checkout must revalidate stock and atomically reserve/decrement inventory on verified payment events.
- Only the supplied heart has a Wonder Card. There are no physical fulfillment or print workflows yet.
- No founder biography, About page or empty Journal section was invented.

## SEO, media and accessibility

Product routes render product-specific metadata, canonical URL, Open Graph/Twitter images and escaped Product JSON-LD. Offers are emitted only for a seller-confirmed price and known availability; no fake ratings or reviews. Preview indexing is disabled centrally (`indexingEnabled` in `lib/seo.ts`); robots and sitemap are prepared for launch. Enable indexing only after copy/prices/availability are reviewed and access is intentionally public.

Hero covers have 320/640/960px WebP variants generated by `scripts/optimize-covers.mjs`. Original files are untouched. The complete set of 640px covers is about 1.64 MB versus 16.09 MB for existing staged originals (~90% smaller); this is an asset-byte comparison, not a measured Core Web Vitals claim. New uploaded covers use originals until variants are generated for them. Fonts remain local system stacks; no font network requests were added.

The first detail image is prioritized, subsequent images are lazy, original handheld films stay available with muted playback and controls, offscreen pause and tap-to-play fallback. Original video compression is unchanged. Discovery advances every six seconds and retains manual pause/reduced-motion behavior. Header and mobile media-first ordering are preserved. Text uses warm off-white/stone tokens, story measure stays around 65 characters, facts and Wonder Cards have separate semantic sections. No device/browser visual audit or Core Web Vitals field measurement has been performed in this pass.
